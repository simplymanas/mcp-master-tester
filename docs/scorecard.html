MCP server scorecard

Every month I list the tools of the 10 most downloaded servers in the official MCP Registry, and of the servers from the first survey, and measure what each sends to the model on every request. Only the tool list is read: no tool is called.

What the numbers say

  • Size: 5 servers send over 10,000 tokens with every request: Fallow (37,109), Firecrawl MCP (22,019), Notion MCP (17,474), Azure MCP (15,635), Desktop Commander (10,280). Lint warns at about the same point, by its own estimate.
  • Safety labels: 375 of 406 tools have annotations such as readOnlyHint. 8 servers label none of their tools.
  • Parameters: 276 of 1,819 parameters have no description of their own.
  • Spec errors: no server has a lint error, such as an input schema that isn't an object or a duplicate tool name.

The registry as a whole

The official registry lists 74,014 servers (latest versions, not counting 1,127 deprecated), 34,343 of them published or updated in the last 30 days. 45,425 are remote only, 22,896 are packages only and 4,987 are both. They come from 45,179 publishers, and the 10 largest account for 13,068 servers (18%), which is why the scorecard ranks by downloads instead of measuring the whole list.

Method

  • When: 26 November 2026, by a scheduled GitHub Actions workflow in this project's repository. The results arrive as a pull request, which I review before it's published.
  • Which servers: the 10 registry servers whose npm or PyPI package had the most downloads in the last 30 days, run over stdio, plus the servers from the first survey. Download counts come from npm's public API (for scoped packages, from npm's search results, which cover the 5,000 most relevant "mcp" packages) and from the public PyPI download dataset. Downloads count every install of a package, so a large tool that also includes an MCP server, such as a cloud provider's command line, ranks by all its users. Remote-only servers have no download counts, so only the survey's remote servers are included.
  • How: each package is the version the registry lists, run with npx or uvx and only the arguments and environment defaults its registry entry gives, read the way the registry's schema defines them. A server whose entry doesn't give a working command is listed as not started; its publisher can fix the entry. No key or token is supplied. Each runs inside a container with no access to the repository's credentials, and its output is checked before use.
  • Only tool lists were read. Each server got initialize and tools/list, nothing else. The lists were checked with MCP Master Tester 1.11.0's lint.
  • Tokens are counted with OpenAI's o200k tokenizer (the one GPT-4o and later use), over each tool definition as compact JSON. Claude's tokenizer isn't published, and other models count differently, so compare servers with each other rather than reading a figure as exact for every model. Clients also wrap tool lists in their own format, which adds a little. The counts include output schemas, which not every client passes to the model; where a server declares them, the table also gives the count without them.
  • Earlier figures were estimates. The first survey, and lint, estimate tokens as characters divided by four, which comes out about 13% higher than o200k across the survey's servers. The data files keep both. Thanks to a reader on LinkedIn whose question led to the real counts.
  • Settings change the numbers. Several servers can expose fewer tools through their options. These figures are for the defaults.
  • The data: every month's numbers are in docs/scorecard as JSON.

I make MCP Master Tester, the tool used for these checks. If a number here is wrong, or your server needs a setting to start, please open an issue.
